# サウンドの生成

`public/static/assets/sounds/` のサウンドは、`tools/sounds/` の Python スクリプトで作曲(MIDI)とレンダリング(音声)を行って生成します。GarageBand は使いません。

| 名前 | 内容 |
| --- | --- |
| Zerc | NecOS の既定の起動音(約5.5秒) |
| Zercone | Zerc のモチーフを展開した曲(約3分、120 BPM、ハ長調) |
| Mirai | 128 BPM・イ短調の曲(約2分36秒) |
| `user-interface/*` | 着信音・アラーム・通知音の9種類(後述の「ユーザーインターフェースのサウンド」) |

## ビルド

```bash
cd tools/sounds
uv run build.py                          # すべて
uv run build.py zerc                     # 1曲だけ
uv run build.py user-interface           # ディレクトリ単位(user-interface/ の9種類)
uv run build.py user-interface/ringtone  # サブディレクトリの1曲
uv run build.py --output /tmp/preview --format .wav
```

- 依存関係は numpy だけで、出力を再現できるようバージョンを固定しています。`build.py` 先頭の PEP 723 メタデータにより、`uv run` が専用の環境を用意します。Webサイト本体(`pyproject.toml`)の依存関係には含めていません。サイトの実行には不要で、Dockerイメージを大きくしないためです。
- エンコードに FFmpeg(`libmp3lame` と `flac`)が必要です。
- 出力は曲ごとに `.mid`(楽譜)、`.flac`(48 kHz / 24 bit の原本)、`.mp3`(256 kbps)です。
- 同じ環境では、出力はビットごとに一致します(乱数はすべて固定シードで、Python の `hash()` は使わず、エンコーダーのバージョン情報も書き込みません)。CPU によって numpy の三角関数などの計算結果が最下位ビットで異なる場合があるため、別のマシンでは完全には一致しないことがあります。
- テスト: `uv run --with numpy --with pytest pytest tools/sounds/tests`

## 構成

| ファイル | 役割 |
| --- | --- |
| `midi.py` | Standard MIDI File(フォーマット0/1)の読み書き。標準ライブラリだけで動きます |
| `score.py` | 拍単位・音名で MIDI トラックに書き込む補助(`Part`, `Score`)と曲の基底クラス `Song` |
| `dsp.py` | 信号処理の基本(`Signal`, `Envelope`)と音源(`Additive`, `FM`, `Analog`, ドラム各種, `Sweep`) |
| `effects.py` | `Reverb`, `Delay`, `Limiter`, `Loudness`(ITU-R BS.1770-4) |
| `mixer.py` | MIDI のトラックごとに `Strip`(ミキサーのチャンネルストリップ: 音源・音量・パン・センド)で鳴らし、ダッキングとマスター処理をして音声にする。`Mixer.mix()` がマスター処理前のバス、`Mixer.render()` がマスター処理後の音声を返す |
| `audio.py` | FFmpeg による書き出し |
| `songs/*.py` | 各曲の楽譜と音色・ミックスの設定。`interface.py` はユーザーインターフェースのサウンドの共通部分(基底クラス `Interface`)、`notifications.py`・`alarms.py`・`ringtone.py` が各サウンド |
| `build.py` | コマンドラインの入口 |

曲は `Song.directory` で出力先のサブディレクトリを指定できます。`Song.path()`(例: `user-interface/ringtone`)が出力先の相対パスで、コマンドラインでの名前でもあります。

処理の流れ: `Song.compose()` が `MIDIFile` を作る → `.mid` に書き出す → **書き出した `.mid` を読み直して** `Mixer` がレンダリングする → マスタリング(ラウドネス正規化とリミッター)→ FFmpeg でエンコード。読み直すことで、`.mid` が音声の唯一の元データであることを保証しています。

### 音名

`midi.py` の `Pitch` は科学的音名表記(中央ハ = C4 = 60)です。**GarageBand と Logic は同じ音を C3 と表示します。** GarageBand の画面と照らし合わせるときは、1オクターブずれることに注意してください。

### 音源の設計

- numpy にはサンプル単位の再帰フィルタ(IIR)がなく、Python のループで書くと3分の曲で非常に遅くなります。そのため:
    - 波形はすべて倍音の和(加算合成)か FM で作ります。ナイキスト周波数を超える倍音を作らないので、折り返し雑音(エイリアシング)が原理的に出ません。
    - アナログシンセ風の `Analog` は、ノコギリ波などを倍音ごとに生成し、時間変化するローパスフィルタの振幅特性を倍音ごとに掛けて再現します。倍音は `sin((k+1)x) = 2cos(x)sin(kx) - sin((k-1)x)` の漸化式で求め、`sin` の呼び出しを省いています。
    - 固定フィルタ(EQ、ノイズの帯域制限など)はゼロ位相で掛けます。短い信号は1回の FFT で、曲全体のような長い信号は、同じ振幅特性から作った窓付き FIR をブロック単位で畳み込みます(曲の長さの FFT を避け、メモリ使用量を抑えるため)。
- CC7(ボリューム)と CC11(エクスプレッション)は General MIDI に従い、最初のイベントまでは 127、次のイベントまでは値を保持し、振幅は (値/127)² です。段差によるノイズを避けるため、変化は 10 ms かけて滑らかにつなぎます。
- 同じ音高で重なるノートは MIDI では区別できず往復で壊れるため、書き出し時にエラーにしています。
- 同じ音高・強さ・長さの音はキャッシュして再利用します(Zercone のようにループの多い曲で大きく効きます)。
- リバーブは、帯域ごとに減衰時間の異なるノイズで作ったインパルス応答の畳み込みです(高域ほど早く減衰)。畳み込みはブロック単位の overlap-add なので、曲の長さに対してメモリ使用量が増えすぎません。
- ラウドネスは BS.1770-4 の積分ラウドネス(K特性、400 msブロック、絶対ゲート -70 LKFS、相対ゲート -10 LU)で測ります。K特性は libebur128 と同じ方法で任意のサンプリング周波数向けに設計した2つの双二次フィルタの振幅特性です。EBU Tech 3341 のテストケースで検証しています。正規化は2回行います(音量を下げると -70 LKFS の絶対ゲートをまたぐブロックが出て、測定値がわずかに動くため)。
- 目標ラウドネス: Zerc と Zercone は -16 LUFS、Mirai は -15 LUFS。ピークは -1 dBFS 以下(MP3 化での振幅のはみ出しを避ける余裕)。

### ループ

着信音・アラーム・非常事態の通知は、止めるまで繰り返し鳴らすため、つなぎ目のないループとして書き出します(`Master.loop` に長さを秒で指定)。

- ループの長さに `Master.tail` を足した長さでレンダリングし、ループの終わりからはみ出した部分(リバーブ、ディレイ、ループの境界をまたいで伸ばした音)を先頭に足し戻します(`Signal.fold`)。何周も繰り返したあとの定常状態と同じ音になります(`tests/test_loops.py` で、6周続けてレンダリングした5周目と一致することを確認しています)。`tail` はリバーブとディレイが十分に減衰する長さにしてください。
- エフェクトは音を時間的に前へも広げることがあります(ディレイは入力をゼロ位相フィルタで帯域制限します)。ループの先頭より前に広がった分は前の周の終わりに属するため、エフェクトの前にループ1周分の余白を先頭に置き、処理後に回転してから折り返します。
- 折り返した残響は、最初の1周目の冒頭にも入ります(前の周がないのに、その残響が聞こえる)。これを小さくするため、各ループの最後の小節は早めに音を減らしています。最初の100 msに入る残響は、ループ全体の RMS に対して ringtone -16 dB、alarm-default -18 dB、alarm-wakeup -13 dB、alert -57 dB です。どれも、最初の小節と協和する音だけです。
- マスターのハイパスは、ループを1周期とする周期信号として掛けます(`Signal.filter(..., circular=True)`)。リミッターは、同じループを3つ並べて処理した中央を使います(`Limiter.process(..., circular=True)`)。どちらも、ループの終わりと始まりが互いに影響し合うようにするためです。ループにはフェードアウトを付けません。
- すべての音はループの中で始まる必要があります(外で始まる音はエラーにします)。
- MP3 はエンコーダーの遅延とパディングを先頭と末尾に加えます。FFmpeg は LAME ヘッダーにその長さを書き込み、FFmpeg 自身のデコーダーはこれを使って元の長さに戻します(確認済み)。ただし、ブラウザーの `<audio loop>` や Android の MediaPlayer などがこれを使うとは限らず、つなぎ目にわずかな無音が入ることがあります。継ぎ目なく繰り返す必要がある場合は、FLAC を使うか、デコードした音声を Web Audio の `AudioBufferSourceNode`(`loop = true`)で再生してください。
- ループの長さは拍で書き、`Interface.seconds()` でテンポから秒に直します。テンポを変えてもループの長さがずれないようにするためです。

### 検討して採用しなかった方法

- **SoundFont と FluidSynth などの外部シンセ**: 音色が外部のサンプル素材に依存し、そのライセンスと入手性に縛られます。「音源を自作する」という目的にも合いません。
- **scipy の利用**: IIR フィルタは使えるようになりますが、依存関係が増えます。上記の方法で numpy だけで足りました。
- **GarageBand のループ素材(Apple Loops)を MIDI に書き起こすこと**: 元の Mirai の旋律パートは Apple Loops のオーディオ素材でした。素材そのものの書き起こしはせず、和声・テンポ・構成だけを引き継ぎ、各パートは新たに書きました。

## 元の GarageBand プロジェクトからの移行

元のファイル(`*.band.7z`、`*.aif`)から、次の情報を取り出して使いました。これらのファイルはリポジトリから削除しました。Gitの履歴から取り出せます。

- `Alternatives/000/MetaData.plist`: テンポ、調、拍子。
- `Alternatives/000/ProjectData`(Logic と共通のバイナリ形式): `qSvE`(EvSq)チャンクにイベント列が入っています。チャンクのヘッダーの28バイト目から8バイト(リトルエンディアン)が本体の長さで、本体は16バイト単位のレコードです。ノートは32バイトで、先頭が `0x90`、4〜7バイト目が位置(960 ticks/四分音符、リージョン先頭が 38400)、11バイト目がベロシティ、12バイト目がノート番号、28〜31バイト目が長さです。リージョンの配置は、`0x20` で始まるレコード(位置、参照するイベント列、トラック、長さ)に入っています。これは公開仕様ではなく、実データから読み取ったものです。
- Zerc の和音と、Zercone の3種類の旋律(イントロ・ヴァース・メイン)、対旋律(Emerald Haze)、各パートの小節配置は、この方法で音符単位で復元し、そのまま使っています。
- Mirai の和声(Fmaj7 – Fmaj7 – Am7 – Cmaj7)は、音声のクロマ分析で求めました。

## 各曲の設計

### Zerc

- モチーフは元のまま: C3 D3 F3+A3 C4 D4 を 0, 1/2, 3/4, 3/4, 1, 3/2 拍(120 BPM)で重ねます。入りの間隔(1/4, 1/8, 0, 1/8, 1/4 秒)は前後対称です。
- 元の音は正弦波だけで、発音のたびにクリック音があり、2.0秒で切れていました。安っぽく聞こえた主な原因です。
- macOS の起動音を参考に、1つの和音が豊かに鳴り、自然に減衰する音にしました。NecOS のロゴの白と灰色の2本の線に合わせて、2つの層で構成しています。
    - 白: モチーフを奏でる FM エレクトリックピアノと、1オクターブ上のベル。
    - 灰: その下で広がるパッド、ベース、高音の「空気」。
- モチーフの下に F の根音を置き、F6/9 の和音にしました。開放的な長和音で、Zercone の冒頭(Fmaj7)とも一致します。元はモチーフの最低音 C が最も低い音でした。

### Zercone

- 旋律は元のプロジェクトのものを音符単位でそのまま使っています(ベロシティは元がすべて98だったため、拍の位置に応じて少し強弱を付けています)。
- 追加したもの: 和声(1小節ごとに Fmaj7 – Dm7 – C – G7sus4 / Fmaj7 – Dm7 – Am7 – G7sus4。イントロは同じ進行を2小節ごと)、ベース、自作のドラム、セクションの切れ目のフィルとライザー、エレクトリックピアノの後半のコード伴奏。
- 元の楽器配置(各パートが入る小節)はほぼ維持しています。最後のセクションはヴァースの旋律に戻し、曲の最後に Zerc の起動音を置いて締めくくります。

### Mirai

- テンポ・調・和声と、元のプロジェクトのセクション構成(イントロ、ドラム、アルペジオ、ブレイク、旋律、アウトロ)を引き継ぎ、すべてのパートを新たに書きました: パッド、ベース、16分音符のアルペジオ、16小節の旋律、ベル、ドラム、ライザー。
- 元の曲は最後の和音(C)でそのまま終わっていました。主和音(Am(add9))に解決して余韻を残して終わるようにしています。

## ユーザーインターフェースのサウンド

`public/static/assets/sounds/user-interface/` には、次の9種類を置いています。

| 名前 | 用途 | 長さ | ループ | ラウドネス |
| --- | --- | --- | --- | --- |
| `ringtone` | 着信音 | 8秒 | ○ | -14 LUFS |
| `alarm-default` | アラーム・タイマー | 4秒 | ○ | -16 LUFS |
| `alarm-wakeup` | 起床アラーム | 16秒 | ○ | -14 LUFS |
| `notification-information` | 情報(対応の必要がないもの) | 約3秒 | | -21.5 LUFS |
| `notification-default` | 通常の通知 | 約3.2秒 | | -18.7 LUFS |
| `notification-message` | メッセージ | 約2.9秒 | | -18.6 LUFS |
| `notification-warning` | 注意 | 約3.2秒 | | -16 LUFS |
| `notification-caution` | 重要な通知 | 約3.8秒 | | -15 LUFS |
| `notification-alert` | 非常事態(地震など) | 8秒 | ○ | -12 LUFS |

単発の通知の長さには、余韻(リバーブ)が含まれます。音が鳴っている部分は最初の0.1〜1.2秒です。どれも最初のサンプルから音が始まるので、再生の遅れが出ません。

### 使い方

- ループのサウンドは、止めるまで繰り返し再生してください。継ぎ目なく繰り返すには FLAC を使います(上の「ループ」を参照)。
- 起床アラームは、スマートフォンの「徐々に音量を上げる」と同じように、再生側で数十秒かけて音量を上げることを推奨します。眠っている人を急に大きな音で起こさないためです。ファイルの中で音量を上げる方式は、ループと両立しないため採用しませんでした(後述)。
- ラウドネスは重要度の順に上がるように決めています。再生側で個別に音量を揃えると、この差が失われます。

### ラウドネスの決め方

- 表のラウドネスは BS.1770 の積分ラウドネスです。短い音では、余韻の長さで積分値が変わり、聞いたときの大きさとずれます。そこで、最も大きい400 ms(最大モーメンタリーラウドネス)も重要度の順に上がるように目標値を調整しました(information -16.8、default -14.1、message -14.5、warning -13.3、caution -12.1、alert -10.5 LUFS。alarm-default -12.5、ringtone -12.0、alarm-wakeup -12.5 も alert より下)。warning は information に近い緊急度という位置づけのため、通常の通知とのわずかな差にとどめています。層の構成を変えると、同じ積分ラウドネスでもこの値が1 dB 程度動くため、変更のたびに測り直してください。
- スマートフォンのスピーカーは低音をほとんど鳴らせません。700 Hz の4次ハイパスをスピーカーの粗いモデルとして掛け、最大モーメンタリーラウドネスもこのモデルで重要度の順になることを確認しています(information -21.6、default -17.2、message -17.4、warning -15.3、caution -13.4、alert -12.7 LUFS。alarm-default -13.1、ringtone -13.6、alarm-wakeup -13.9)。心地よい通知は音程を下げたため(後述)、このモデルでは積分ラウドネスが2〜4 dB 小さくなります。default では1オクターブ上のプラックがスピーカーでの聞こえを補っています。起床アラームは当初、低音が多く、このモデルで -18.6 LUFS と最も小さかったため、ベースとパッドを下げ、ベルを上げ、目標を -14 LUFS にしました。

### 共通の設計

- **1つの音で作らず、層で作る**: どのサウンドも、Zerc と同じように複数の層を重ねます。どの層も聞こえる大きさにし、1つの層がエネルギーの6割を大きく超えないようにしています。
    - 心地よい通知: 芯(`tone` かプラック)、明るい層(プラックや `shimmer`)、ふくらみ(`bloom`: 5声の少しずつずらしたのこぎり波の和音で、芯の下で膨らみ、約1秒で消える。厚み・広がり・時間変化を与える)、低音(`sub`: 1〜2オクターブ下の三角波)。
    - 警告: 心地よい通知と同じ層(`tone`、ふくらみ、低音、`shimmer`、エコーと残響)に、警告の旋律と、緊急度を担うシグナル(`signal`)を加えます。各パルスは `signal` と `tone`(中央)、ハロー(`halo`: 1オクターブ上の丸い音。パルスごとに左右に振り分ける)、ボディ(1オクターブ下の短い三角波。次のパルスの前に消える)で鳴ります。`signal` の割合は warning 約12%、caution 約29%、alert 約46%と段階的に増やします。caution と alert は `tone` の余韻を短くし(0.12秒)、パルスが1つずつ聞こえるようにしています。
    - 着信音・アラーム: パッドとベースが和音を支える。着信音と起床アラームの後半は、柔らかいキックに合わせてパッドが沈む(サイドチェイン風のダッキング)控えめなビートを持つ。
- **中心を定め、広がりは別の層で作る**: 芯になる層(`tone`、`whistle`、`shimmer`)は単声で、左右で音程をずらしません。広がりは、プラック・ふくらみ・パッドの複数の声部、パン、エコー、残響で作ります。
- **現在の OS の音に合わせた、楽器を模さない音色**: 次の資料を参考に、アコースティック楽器(エレクトリックピアノ、ベル、マリンバ)をやめ、合成の音色にしました。
    - Windows 11 の音は「デジタルに彫刻された」もので、文化による連想を避けるため楽器を想起させないように作られ、Windows 10 の「鋭い波形」より「丸い波形」で、音程は低め、高低の振れ幅は小さく、最後の音を長く伸ばしません。ダークモード用はより柔らかく、軽いエコーがあります(CNBC 2021、BleepingComputer 2021)。
    - iOS 17 の既定の通知音 Rebound は、雨粒のような柔らかい2音に残響のエコーが付いた音です(9to5Mac 2023)。
    - iOS 26 では、着信音 Reflection の電子的なリミックス6種と、EDM 調のベースラインに口笛の旋律を重ねた Little Bird が加わりました(MacRumors 2025)。
    - 使う音色(`Interface`): `tone`(三角波が12 msで半音下から音程に滑り込む、しずくのような丸い音。フィルターで一瞬だけ明るい縁を付ける)、`pluck`(3声ののこぎり波を素早く閉じるフィルターに通したシンセのプラック)、`whistle`(すくい上げとビブラートのある、ほぼ正弦波の口笛風リード)、`shimmer`(1オクターブ上の正弦波)、`halo`(警告用、1オクターブ上の三角波)、`signal`(警告用、後述)。音程の滑り込みのため、`Analog` に `bend`/`bend_time` を追加しました(上へ滑る場合も倍音がナイキスト周波数を超えないよう、最も高い音程から倍音の数を決めます)。
- **空間**: 部屋の響きではなく、エコー(付点8分、0.375秒のピンポン)と柔らかく暗い余韻で奥行きを作ります(Rebound や Windows 11 のダークモード用の音のような、軽いエコー)。共有の残響(`Interface.room()`)は初期反射を弱くし(0.08)、高域を早く減衰させ(damping 0.25)、1.6秒、プリディレイ30 ms・低域カット150 Hz です。警告用(`booth()`)はプリディレイ25 ms・1.1秒で、送る量も少なく、パルスどうしが混ざらないようにしています。
- **Zerc と同じ一族にする**: テンポ(120 BPM、1拍0.5秒)、調(ヘ長調)、Zerc のモチーフと Zerc 系のパッドを共有します。心地よいサウンドは Zerc の和音 F6/9 の音(F G A C D、ヘ長調の五音音階)だけで作り、着信音は Zerc のモチーフそのものを使います。
- **警告は同じ音階の別の響きにする**: 注意・重要・非常事態は、同じ五音音階のうち G・D・A だけを使います。4度で積んだ、長調でも短調でもない(明るくも悲しくもない)真剣な響きです。一族としての一貫性を保ちながら、心地よい通知とははっきり区別できます。
- **緊急度の段階**: 聴覚警報の研究(Edworthy, Loxley & Dennis 1991、Hellier et al. 1993)で、人が一貫して「より緊急」と感じることが分かっている要素を、段階的に強めています: パルスの数、速さ(最も効果が大きいのは速さ)、繰り返し、音色の硬さ、音量。

| 名前 | 音型 | 間隔 |
| --- | --- | --- |
| information | 2音(A→F、3度下がる) | 125 ms |
| default | 2音(C→F、4度上がって主音へ) | 125 ms |
| message | プラックの3音(D F A) | 94 ms |
| warning | 3パルス(高・低・高) | 180 ms |
| caution | 4度の重音で3パルス × 2回 | 150 ms |
| alert | 重音で低・高・低・高の4パルス × 2回を2秒ごとに繰り返す | 125 ms |

- **警告のシグナルの音色**(`Interface.signal()`): 医用電気機器の警報の規格 IEC 60601-1-8 の考え方(二次資料による)に従い、caution と alert のパルスは、基本周波数を150 Hz〜約1 kHz(最も高い D6 は1175 Hz)に置き、すべての層を合わせた第1〜第4倍音を15 dB 以内にしています(実測で10〜13.5 dB。`tests/test_interface.py` で全音高を確認)。小さなスピーカー、騒音下、高音域の聴力が落ちた人でも聞き取りやすく、音の方向も分かりやすくなります。
    - 1声ののこぎり波を、音程に追従する4次のローパス(基音の約4倍)に共鳴を付けて通し、第2〜第4倍音を基音と並べ、第5倍音より上を落として耳障りにならないようにしています。1オクターブ上の `halo` が第2・第4倍音を補います。立ち上がりは8 msで、わずかに音程へ滑り込みます。
    - 3声のユニゾンにすると、声部どうしのうなりで倍音の比が刻々と変わり、音高によっては条件を外れたため、1声にしています(広がりは `halo` で作ります)。
    - 丸い `tone` が強いと基音だけが大きくなり条件を外れます(独立したレビューで、合成したパルスの差が17〜25 dB と判明)。caution・alert では `tone` を小さくし、奥行きはパルスの外のふくらみと低音で作っています。
    - warning は information に近い緊急度の音として、この条件の対象外にしています(差は約17 dB)。
    - 以前は2オペレーター FM のチャイムを使っていました(第 k 倍音の振幅は J(k-1) + (-1)^k J(k+1) で、基音 J0 - J2 は変調指数約1.84で0になるため、変調指数を3.2〜3.8にしていました)。所有者から警告系が安っぽく奥行きがないと指摘され、2000年代の携帯電話の「デジタルなベル」に近い音色だったため、警告からは外しました。alarm-default ではプラックの1オクターブ下で今も使っています(`Interface.chime()`)。
- **耳障りにしない**: 3 kHz 付近(外耳道の共鳴で鋭く聞こえる帯域)に音を集めず(2.5〜5 kHz のエネルギーは心地よい音で全体の1〜2%、警告で8〜14%)、柔らかい立ち上がりの楽器を使います。半音でぶつかる音(短2度・短9度)が同時に鳴らないことを楽譜の上で確認しています(長7度の和音は意図的に使っています)。

### 各サウンドの設計

- **ringtone**: 部屋の離れた所からでも「自分の電話だ」と分かるよう、Zerc のモチーフ(C D F+A C D、同じリズム)を2オクターブ上(小さなスピーカーでよく鳴る音域)で毎小節繰り返します。モチーフは丸い `tone` にプラックを重ね、1オクターブ上に `shimmer` を添えます。和声が F6/9 → Dm7 → B♭maj9 → Csus4 と動き、モチーフはそのすべてに合います。口笛風のリードが毎回下降する応答(A G, F D, C A, D G)を返し、最後に上がって冒頭へ戻ります。ベースより上の音はすべてモチーフの五音音階(F G A C D)で、最後の小節も E に解決しないため、残響やディレイの中でも半音でぶつかる音がありません。iOS 26 のリミックスのように、柔らかいキック(1・3拍)、クラップ(2・4拍)、ハイハット(裏拍)の控えめなビートがあり、パッドとベースはキックに合わせて沈みます。
- **alarm-default**: 目覚まし時計の「4つの短い音・休み」の周期(誰でもすぐアラームと分かる形)を、ブザー音ではなくプラック・`tone`・チャイムの和音のアルペジオで鳴らします。パッドとベースが休みの間も和音(F, F, G-D-A, F)を支え、最後の和音は早めに切ってループの冒頭へ残響が入りすぎないようにしています。
- **alarm-wakeup**: McFarlane らの小規模な研究では、起きるときの音を「メロディーがある」と評価した人ほど寝起きのだるさ(睡眠慣性)が少ないと答え(PLOS ONE 2020、50人の自己申告の調査)、メロディーのあるアラームでは対照の音より起床後の注意力の検査の成績が良く、リズムだけのアラームでは差がありませんでした(Clocks & Sleep 2020、20人)。著者自身も予備的な結果としています。そこで、最初から最後まではっきりした旋律(口笛風のリード)のある短い曲にし、8分音符で一定に刻む柔らかいプラック、丸い音色、スマートフォンのスピーカーでも鳴る300 Hz〜2 kHz を中心にしました(2〜4 kHz のエネルギーは全体の約2%)。8小節を前後半に分け、どちらにも旋律があります。後半は旋律を強く弾き、シェイカーと柔らかいキック(パッドがキックに合わせて沈む)が加わりますが、前半との差は約0.7 dB にとどめ、ループで戻ったときに急に弱くならないようにしています。最後の小節は Csus4 のまま E に解決せず、冒頭の F と半音でぶつからないようにしています。
- **notification-information**: 最も控えめな音。default と最初から最後まで違う形にしています: default は C から F へ上がって明るい F の和音に落ち着き、エコーで2回繰り返します。information は A から D へ5度下がり(Windows 11 の「1音、次に低い音」と同じ形)、エコーを使わず、柔らかい D マイナーの響き(D F A)のふくらみと D の低音の上で、D の `shimmer` が小さく残ります。どちらも F6/9 の音だけです。0.3秒以降の音の成分(クロマ)は、information が D 中心、default が C と F 中心で、類似度は0.1〜0.7です。
    - 当初は和音1つで、余韻が default と同じ F の和音だったため、鳴り始めしか違わず区別しにくいという指摘を受けました。次に A から F へ3度下がる形にしましたが、余韻がどちらも F と F6 に収束し、独立したレビューで違いが約0.1秒しか続かないと分かったため、現在の形にしました。
- **notification-default**: C5 から F5 へ4度上がって主音に落ち着く、しずくのような2音。「届いた」ことを表します。1オクターブ上でプラックが重なり、F でふくらみと低音が入ります。
- **notification-message**: プラックの速い3音(D5 F5 A5)に丸い `tone` を重ねます。話し声のような速さで上がり、開いた3度の音で終わって返事を待つような形にしています。
- **notification-warning**(注意): 緊急度は information に近いため、information と同じ音色・空間(丸い音、ふくらみ、低音、`shimmer`、エコー)に警告の旋律を乗せています。高・低・高(A5 D5 A5)の3音を180 ms間隔で鳴らし(高低の交替は最も広く「警告」と理解される型)、落ち着いた和音ではなく D・G・A の宙づりの響きのふくらみの上で、高い音で開いたまま終わって確認を促します。`signal` は薄い縁取り程度です。
- **notification-caution**(重要): 同じ型を4度の重音(A5+D6 / D5+A5)にし、速く(150 ms)、2回鳴らします。`signal` とボディを増やし、より低い G・D・A のふくらみと G の低音を置きます。
- **notification-alert**(非常事態): 確実に気づき、緊急だと分かり、落ち着いて行動できること、そして周囲の多くの端末で少しずつずれて同時に鳴ることを考えて設計しました。
    - 一族で最も速く、音域が広く、大きい音で、独自の形を持ちます。G4+D5 と A5+D6 の間を低・高・低・高と跳躍する4パルスを125 ms間隔で2回、2秒ごとに繰り返します。caution が1オクターブの中で動くのに対し、alert は1オクターブ以上跳び、高い音で終わります(速さ、音域の広さ、上昇、繰り返しはどれも緊急度を高めます)。当初は caution より低い音域で、形も似ていたため、区別しにくいという指摘を受けて変えました。
    - 基本周波数は約390〜1170 Hzで、倍音が1〜4 kHz を埋めます。
    - 耳障りにしない: 不協和な音程ではなく5度・4度の協和音程、丸い立ち上がり、鋭い高音を使わないこと。
    - 2秒ごとに休みがあり(10 ms ごとの RMS が最大より30 dB 以上小さい時間が約0.8秒)、その間に放送や周りの人の声が聞こえます。複数の端末がずれて鳴っても、リズムの形が崩れにくくなります。奥行きのために各グループの下に短い G・D・A のふくらみと低音を置きますが、余韻を短くして(0.25秒・0.2秒)休みに入る前に消えるようにし、残響は乾いた `booth()`、エコーは使いません。`signal` が最も多く(約46%)、明瞭さと到達距離を担います。リミッターが約2 dB 効きます(共鳴のあるのこぎり波はピークが鋭いため)。
    - すべての音が G・D・A なので、ずれて重なった音どうしも同じ和音になり、ぶつかりません。
    - 公式の警報音(緊急地震速報のチャイム、Jアラートのサイレン、米国の EAS/WEA の 853 Hz + 960 Hz の注意喚起信号)とは意図的に似せていません。本物の警報と取り違えられたり、本物の警報が聞き分けにくくなったりしないようにするためです。米国では、EAS の注意喚起信号やその模倣を、実際の緊急時と認められた試験以外で送信することが FCC 規則(47 CFR 11.45)で禁止されています。緊急地震速報のチャイムを作った伊福部達氏が挙げた条件(注意を喚起する、すぐ行動したくなる、既存の警報音と異なる、極端に不快でも快適でもない、聴覚障害者にもできるだけ聞こえる)も参考にしています。

### 検討して採用しなかった方法

- **起床アラームのファイルの中で音量を徐々に上げる**: ループで繰り返すと周の始まりで急に小さくなり、ループにしないと長さが足りなくなります。音量を上げるのは再生側の役割(iOS・Android と同じ)としました。
- **警告音に方形波・のこぎり波のビープを使う**: 倍音の条件は満たせますが、安っぽく、高域が耳障りです。倍音の量を変調指数で連続的に決められる FM にしました。
- **IEC 60601-1-8 の高優先度のパルス列(10パルスの繰り返し)をそのまま使う**: 病院の医療機器の警報と混同されるおそれがあるため、パルスの数と間隔は独自にしました。
- **非常事態の音を連続音(サイレンや持続音)にする**: 複数の端末が同時に鳴ると、うなりや干渉で不快な音になり、声も聞こえなくなります。

### 改訂の経緯: 「奥行きが浅く、安っぽい」

最初の版を試聴した所有者から、alarm-wakeup 以外は奥行きが浅く安っぽい、単一のシンプルな音でできているからではないか、という指摘がありました。独立したレビュー(測定とコードの調査)で、次の原因が分かりました。

- 実質的に1つの音: 主な層がエネルギーの70〜96%を占め、ベルなどは15〜20 dB 小さく、ほとんど聞こえなかった(alarm-wakeup はどの層も30%前後)。
- その音もほぼ正弦波: Zerc のエレクトリックピアノは、約430 Hz より上では金属的な立ち上がり(tine)が無効になる(側帯波がナイキスト周波数を超えるため)。さらに弱いベロシティでは変調指数が下がり、0.4秒後には基音と -19 dB の第2倍音だけになっていた。
- 低音がない: 400 Hz 以下のエネルギーが0%(alarm-wakeup は24%、Zerc は77%)。
- 不安定なステレオ: すべての楽器が左右で数セントずつずれたコピーで、相関がほぼ0。ヘッドホンでは2〜5 Hz のうなり、モノラルでは最大 -11 dB の音量の揺れになっていた。1セントでも、ラ(A5)の音で0.5秒後に -15 dB の落ち込みが残った。
- 減衰するだけで動きがない: どの倍音も単純な指数減衰で、膨らみや時間変化がない。同じ音のパルスはビット単位で同じだった。

これを受けて、上の「共通の設計」のとおり層で作り直しました。各層のエネルギーの割合、400 Hz 以下の割合、左右の相関、2.5〜5 kHz の割合、ラウドネスの順序を測定して調整し、再度独立したレビューを受けています。

検討して採用しなかったもの:

- **Zerc のエレクトリックピアノの tine の比率を音ごとに下げて残す**: 音高によって比率(音色)が変わってしまうため、独立した打音の層にしました。
- **ベルに1セント程度のデチューンを残す**: 小さくしても、うなりの最初の谷が遅れるだけで、聞こえている間に起きました。

### 改訂の経緯: 「安っぽさは減ったが、モダンさがない」

層で作り直した版について、所有者から、安っぽさは減ったがモダンさがない、マリンバやベルが主体で、Windows 7(ベル系)と Windows 11 の違いのように音源の選択が古い、という指摘がありました(所有者は Windows の中では Windows 10 の音を最も好んでいます)。上の「現在の OS の音に合わせた、楽器を模さない音色」のとおり、エレクトリックピアノ・ベル・マリンバ・打音(`strike`)を合成の音色に置き換えました。旋律・和声・リズム・層の構成・ラウドネスの順序は変えていません。

その後の独立したレビューを受けて、次も変えました。

- 警告で FM のチャイム(2000年代の携帯電話の「デジタルなベル」に近い)が6割以上を占めていたため、約35%に下げ、丸い `halo` とプラックを増やしました。それでも所有者から、警告系はあまり変わらず奥行きがなく安っぽい、warning は information に近い緊急度なので information をもとに警告の旋律を加えるべき、という指摘があり、警告を心地よい通知と同じ構成で作り直し、チャイムを `signal` に置き換えました(上の「警告のシグナルの音色」)。
- 残響を、部屋らしい初期反射から、エコーと柔らかい余韻に変えました(上の「空間」)。
- Windows 11 に合わせて、心地よい通知の音程を1オクターブ下げました(F5〜F6 から C5〜A5 へ)。
- キックがスマートフォンで聞こえず、パッドが音源の分からないまま沈んでいたため、キックの立ち上がりを高くし(180 Hz から)、ダッキングを弱めました。ハイハットの10 kHz 以上も抑えました。
- 口笛風のリードのビブラートを浅く(14 → 8セント)、遅く始まるようにし、人の口笛の模倣らしさを弱めました。ふくらみのフィルターも下げ、丸くしました。

検討して採用しなかったもの:

- **Windows 11 のように明るい版と暗い版を作る**: 用途ごとに1種類という今回の範囲を超えるため、見送りました。必要になれば、`Interface.room()` の残響とエコー、音量を変えた派生クラスで作れます。
- **警告を丸い音だけで作る**: 倍音が少なく、IEC 60601-1-8 の倍音の目安を満たせず、遠くや騒音下で聞こえにくくなります。倍音を持つ `signal` の割合を緊急度に応じて変えることにしました。
