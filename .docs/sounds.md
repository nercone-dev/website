# サウンド(Zerc / Zercone / Mirai)の生成

`public/static/assets/sounds/` の `zerc`・`zercone`・`mirai` は、`tools/sounds/` の Python スクリプトで作曲(MIDI)とレンダリング(音声)を行って生成します。GarageBand は使いません。

| 名前 | 内容 |
| --- | --- |
| Zerc | NecOS の既定の起動音(約5.5秒) |
| Zercone | Zerc のモチーフを展開した曲(約3分、120 BPM、ハ長調) |
| Mirai | 128 BPM・イ短調の曲(約2分36秒) |

## ビルド

```bash
cd tools/sounds
uv run build.py                 # 3曲すべて
uv run build.py zerc            # 1曲だけ
uv run build.py --output /tmp/preview --format .wav
```

- 依存関係は numpy だけで、出力を再現できるようバージョンを固定しています。`build.py` 先頭の PEP 723 メタデータにより、`uv run` が専用の環境を用意します。Webサイト本体(`pyproject.toml`)の依存関係には含めていません。サイトの実行には不要で、Dockerイメージを大きくしないためです。
- エンコードに FFmpeg(`libmp3lame` と `flac`)が必要です。
- 出力は曲ごとに `.mid`(楽譜)、`.flac`(48 kHz / 24 bit の原本)、`.mp3`(256 kbps)です。
- 同じ環境では、出力はビットごとに一致します(乱数はすべて固定シードで、Python の `hash()` は使わず、エンコーダーのバージョン情報も書き込みません)。CPU によって numpy の三角関数などの計算結果が最下位ビットで異なる場合があるため、別のマシンでは完全には一致しないことがあります。
- テスト: `uv run --with numpy --with pytest pytest tools/sounds/tests`

## 構成

| ファイル | 役割 |
| --- | --- |
| `midi.py` | Standard MIDI File(フォーマット0/1)の読み書き。標準ライブラリだけで動きます |
| `score.py` | 拍単位・音名で MIDI トラックに書き込む補助(`Part`, `Score`)と曲の基底クラス `Song` |
| `dsp.py` | 信号処理の基本(`Signal`, `Envelope`)と音源(`Additive`, `FM`, `Analog`, ドラム各種, `Sweep`) |
| `effects.py` | `Reverb`, `Delay`, `Limiter`, `Loudness`(ITU-R BS.1770-4) |
| `mixer.py` | MIDI のトラックごとに `Strip`(ミキサーのチャンネルストリップ: 音源・音量・パン・センド)で鳴らし、ダッキングとマスター処理をして音声にする |
| `audio.py` | FFmpeg による書き出し |
| `songs/*.py` | 各曲の楽譜と音色・ミックスの設定 |
| `build.py` | コマンドラインの入口 |

処理の流れ: `Song.compose()` が `MIDIFile` を作る → `.mid` に書き出す → **書き出した `.mid` を読み直して** `Mixer` がレンダリングする → マスタリング(ラウドネス正規化とリミッター)→ FFmpeg でエンコード。読み直すことで、`.mid` が音声の唯一の元データであることを保証しています。

### 音名

`midi.py` の `Pitch` は科学的音名表記(中央ハ = C4 = 60)です。**GarageBand と Logic は同じ音を C3 と表示します。** GarageBand の画面と照らし合わせるときは、1オクターブずれることに注意してください。

### 音源の設計

- numpy にはサンプル単位の再帰フィルタ(IIR)がなく、Python のループで書くと3分の曲で非常に遅くなります。そのため:
    - 波形はすべて倍音の和(加算合成)か FM で作ります。ナイキスト周波数を超える倍音を作らないので、折り返し雑音(エイリアシング)が原理的に出ません。
    - アナログシンセ風の `Analog` は、ノコギリ波などを倍音ごとに生成し、時間変化するローパスフィルタの振幅特性を倍音ごとに掛けて再現します。倍音は `sin((k+1)x) = 2cos(x)sin(kx) - sin((k-1)x)` の漸化式で求め、`sin` の呼び出しを省いています。
    - 固定フィルタ(EQ、ノイズの帯域制限など)はゼロ位相で掛けます。短い信号は1回の FFT で、曲全体のような長い信号は、同じ振幅特性から作った窓付き FIR をブロック単位で畳み込みます(曲の長さの FFT を避け、メモリ使用量を抑えるため)。
- CC7(ボリューム)と CC11(エクスプレッション)は General MIDI に従い、最初のイベントまでは 127、次のイベントまでは値を保持し、振幅は (値/127)² です。段差によるノイズを避けるため、変化は 10 ms かけて滑らかにつなぎます。
- 同じ音高で重なるノートは MIDI では区別できず往復で壊れるため、書き出し時にエラーにしています。
- 同じ音高・強さ・長さの音はキャッシュして再利用します(Zercone のようにループの多い曲で大きく効きます)。
- リバーブは、帯域ごとに減衰時間の異なるノイズで作ったインパルス応答の畳み込みです(高域ほど早く減衰)。畳み込みはブロック単位の overlap-add なので、曲の長さに対してメモリ使用量が増えすぎません。
- ラウドネスは BS.1770-4 の積分ラウドネス(K特性、400 msブロック、絶対ゲート -70 LKFS、相対ゲート -10 LU)で測ります。K特性は libebur128 と同じ方法で任意のサンプリング周波数向けに設計した2つの双二次フィルタの振幅特性です。EBU Tech 3341 のテストケースで検証しています。正規化は2回行います(音量を下げると -70 LKFS の絶対ゲートをまたぐブロックが出て、測定値がわずかに動くため)。
- 目標ラウドネス: Zerc と Zercone は -16 LUFS、Mirai は -15 LUFS。ピークは -1 dBFS 以下(MP3 化での振幅のはみ出しを避ける余裕)。

### 検討して採用しなかった方法

- **SoundFont と FluidSynth などの外部シンセ**: 音色が外部のサンプル素材に依存し、そのライセンスと入手性に縛られます。「音源を自作する」という目的にも合いません。
- **scipy の利用**: IIR フィルタは使えるようになりますが、依存関係が増えます。上記の方法で numpy だけで足りました。
- **GarageBand のループ素材(Apple Loops)を MIDI に書き起こすこと**: 元の Mirai の旋律パートは Apple Loops のオーディオ素材でした。素材そのものの書き起こしはせず、和声・テンポ・構成だけを引き継ぎ、各パートは新たに書きました。

## 元の GarageBand プロジェクトからの移行

元のファイル(`*.band.7z`、`*.aif`)から、次の情報を取り出して使いました。これらのファイルはリポジトリから削除しました。Gitの履歴から取り出せます。

- `Alternatives/000/MetaData.plist`: テンポ、調、拍子。
- `Alternatives/000/ProjectData`(Logic と共通のバイナリ形式): `qSvE`(EvSq)チャンクにイベント列が入っています。チャンクのヘッダーの28バイト目から8バイト(リトルエンディアン)が本体の長さで、本体は16バイト単位のレコードです。ノートは32バイトで、先頭が `0x90`、4〜7バイト目が位置(960 ticks/四分音符、リージョン先頭が 38400)、11バイト目がベロシティ、12バイト目がノート番号、28〜31バイト目が長さです。リージョンの配置は、`0x20` で始まるレコード(位置、参照するイベント列、トラック、長さ)に入っています。これは公開仕様ではなく、実データから読み取ったものです。
- Zerc の和音と、Zercone の3種類の旋律(イントロ・ヴァース・メイン)、対旋律(Emerald Haze)、各パートの小節配置は、この方法で音符単位で復元し、そのまま使っています。
- Mirai の和声(Fmaj7 – Fmaj7 – Am7 – Cmaj7)は、音声のクロマ分析で求めました。

## 各曲の設計

### Zerc

- モチーフは元のまま: C3 D3 F3+A3 C4 D4 を 0, 1/2, 3/4, 3/4, 1, 3/2 拍(120 BPM)で重ねます。入りの間隔(1/4, 1/8, 0, 1/8, 1/4 秒)は前後対称です。
- 元の音は正弦波だけで、発音のたびにクリック音があり、2.0秒で切れていました。安っぽく聞こえた主な原因です。
- macOS の起動音を参考に、1つの和音が豊かに鳴り、自然に減衰する音にしました。NecOS のロゴの白と灰色の2本の線に合わせて、2つの層で構成しています。
    - 白: モチーフを奏でる FM エレクトリックピアノと、1オクターブ上のベル。
    - 灰: その下で広がるパッド、ベース、高音の「空気」。
- モチーフの下に F の根音を置き、F6/9 の和音にしました。開放的な長和音で、Zercone の冒頭(Fmaj7)とも一致します。元はモチーフの最低音 C が最も低い音でした。

### Zercone

- 旋律は元のプロジェクトのものを音符単位でそのまま使っています(ベロシティは元がすべて98だったため、拍の位置に応じて少し強弱を付けています)。
- 追加したもの: 和声(1小節ごとに Fmaj7 – Dm7 – C – G7sus4 / Fmaj7 – Dm7 – Am7 – G7sus4。イントロは同じ進行を2小節ごと)、ベース、自作のドラム、セクションの切れ目のフィルとライザー、エレクトリックピアノの後半のコード伴奏。
- 元の楽器配置(各パートが入る小節)はほぼ維持しています。最後のセクションはヴァースの旋律に戻し、曲の最後に Zerc の起動音を置いて締めくくります。

### Mirai

- テンポ・調・和声と、元のプロジェクトのセクション構成(イントロ、ドラム、アルペジオ、ブレイク、旋律、アウトロ)を引き継ぎ、すべてのパートを新たに書きました: パッド、ベース、16分音符のアルペジオ、16小節の旋律、ベル、ドラム、ライザー。
- 元の曲は最後の和音(C)でそのまま終わっていました。主和音(Am(add9))に解決して余韻を残して終わるようにしています。
