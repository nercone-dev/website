# Nepolid
Performance-oriented Linux Distribution

## 概要
Nepolidは機能性とパフォーマンスに特化したLinuxディストリビューションです。
IntelのClear Linuxと同等またはそれ以上に高速な動作を実現することを目的としています。

## 最適化の仕組み

### アロケータ
Nepolidでは、jemallocまたはmimallocをアロケータとして選択できます。

### THP (Transparent Huge Page)
NepolidではTHPが既定で有効です。必要に応じてmadviseリージョン内に制限したり、無効化したりできます。

### パッケージマネージャー
Nepolidは独自のパッケージマネージャーである`nepm` (Nepolid Package Manager)を採用しており、最適化において重要な役割を担います。

`nepm`では N-POP (Nepolid Package Optimization Program) オプションを有効化することで、バックグラウンドでプロファイリングを実行し、Nepolidコミュニティに送信します。

ある程度のプロファイルが集ると、Nepolidコミュニティ側でそれらのプロファイルを反映したバイナリをビルドし配信します。

最適化手法として次のようなものを使用します(BOLT以外はソースコードが公開されているパッケージでのみ使用):

- ThinLTO
- Instrumented PGO
- CS-PGO (CSSPGO)
- `-O3`
- `-march=...`
- `-fno-semantic-interposition`
- Propeller
- BOLT

プロファイルはパッケージのバージョンとISA(AMD製CPUではマイクロアーキテクチャを含む)に紐づけられ、インストール時に次のような優先順位で反映します:

1. 同バージョン、同ISA、同マイクロアーキテクチャの最適化済みバイナリ
1. 同バージョン、同ISAの最適化済みバイナリ
2. 同バージョンの最適化済みバイナリ
3. 旧バージョン、同ISA、同マイクロアーキテクチャの最適化済みバイナリ
3. 旧バージョン、同ISAの最適化済みバイナリ
3. 旧バージョンの最適化済みバイナリ
4. 非最適化済みバイナリ

プロファイルの収集はパフォーマンスへの影響が限定的なレベルにとどめ、また任意で後から有効化できオプションとして実装します。

プロファイルは様々な経路でダウンロードでき、Nepolid以外のディストリビューションでも自由に活用できます。

## コスト問題への対処
Clear Linuxプロジェクトが終了した理由の1つとして、パッケージ/バージョン/ISA毎に最適化を適用したバイナリをビルドする、ということに多大なコストがかかるというものがあります。

Nepolidでは、コミュニティがビルドのための計算資源を提供できます。
`npop-agent`をインストールし実行しておくだけで、マシンをビルドに活用させることができます。

`npop-agent`はNepolidのサーバーと接続し、ビルドの要求を購読します。

サーバーは新規リリース時等に接続元をランダムに選択し、ソースコード等を配信します。

`npop-agent`はサーバーから要求を受信すると、NPCI-PB (Nepolid Pre-configured Image for Package Build)を使用して仮想マシンを作成し、そこでビルドします。

ビルドしたバイナリをサーバーに送信すると、サーバーはそれぞれの送信者から受信したバイナリのハッシュを比較し、より多く一致したハッシュを選択します。

### Sybil攻撃への対応
IP/ASNの多様性チェック、時間軸でのレピュテーション蓄積などの方法でSybil攻撃に対策します。
