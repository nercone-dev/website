Scripts

script.js adds behavior that HTML and CSS cannot provide. Every page must still work without it.

window.nercone

initializer.js defines window.nercone. Each script registers a feature under a name, and the feature is started when the document is ready.

const toast = window.nercone.get('toast'); // the registered feature, or null
toast.show('Hello');
MethodDescription
register(name, feature)Stops the feature registered under name, if any, registers feature, and calls its init() when the document is ready. Returns feature
unregister(name)Stops the feature and removes it
get(name)Returns the feature, or null
cleanup()Calls cleanup() of every feature. Called before a page transition swaps the page
reinit(doc)Calls reinit(doc) of every feature. Called after a page transition, with the new document
navigate(href)Moves to href with a page transition when one is available, or loads it normally

Writing a feature

A feature is any object. It may have these methods, and those it lacks are skipped. Errors thrown by them are logged, so one feature cannot stop the others.

  • init(): starts the feature. Add listeners to document rather than to elements, because a page transition replaces the elements.
  • cleanup(): called before the page is swapped. Close what belongs to the old page.
  • reinit(doc): called after the page is swapped. Update for the new page.
  • destroy(): stops the feature. Called by register() and unregister(); without it, cleanup() is called instead.

A page transition runs a script only once, even when the page that loaded it is opened again, so page scripts should be features as well.

class Clock {
    init() {
        this.timer ??= setInterval(() => this.render(), 1000);
        this.render();
    }
    reinit() {
        this.render();
    }
    destroy() {
        clearInterval(this.timer);
        this.timer = null;
    }
    render() {
        for (const element of document.querySelectorAll('[data-clock]')) element.textContent = new Date().toLocaleTimeString();
    }
}
window.nercone.register('clock', new Clock());

Changing options

Each feature has a class on window.nercone whose constructor takes options. To change them, register a new instance under the same name. The old one is stopped first.

window.nercone.register('toast', new window.nercone.Toast({ position: 'top-center' }));

Page transitions are not a feature but the navigator of window.nercone; see below.

Cursor

A round cursor that follows the mouse. Over a link or button it becomes a box around it, and over text it becomes a thin bar. It is shown only for a mouse; touch and pen input hide it and leave the system cursor. Add the element to <body>:

<div id="cursor" data-view-transition-keep></div>

Elements with cursor-system show the system cursor instead, for places where the exact position matters, such as a canvas. The elements treated as links are set by the linkSelector option. The colors are --color-cursor and --color-cursor-on-link.

Loading overlay

Covers the page while it loads, and draws the logo before fading out. When the system prefers reduced motion, it only fades out. Add it as the first child of <body>:

<div id="loading-overlay" data-view-transition-keep>
    <svg viewBox="96 256 832 512" xmlns="http://www.w3.org/2000/svg">
        <polyline points="872 572.75 152 332 152 692 512 692 872 332 872 692 684.5 692" fill="currentColor"/>
    </svg>
</div>

It is shown only on the first page; page transitions do not show it again. noscript.css hides it when JavaScript is disabled, and it fades out by itself after --loading-overlay-timeout (default 10s) when the scripts fail to load.

Page transitions

In browsers with the View Transition API, view-transition.js moves between pages of the same origin without reloading. It fetches the next page, then swaps the head and the children of <body> while the header and main content cross-fade. When the page cannot be swapped, it is loaded normally.

  • Both pages must have <header> and <main>.
  • Links with target (other than _self) or download, links to other origins, and clicks with a modifier key are left to the browser.
  • Requests have the header X-Requested-With: view-transition.
  • Elements and stylesheets with data-view-transition-keep stay as they are, even when the next page does not have them. The cursor, the loading overlay, the toast container, and the stylesheet added by theme.js have it.
  • Stylesheets of the next page are loaded before the swap, and stylesheets the next page does not have are removed. Scripts are added but never removed, and a script that has run once does not run again.
  • The scroll position is restored when going back and forward.

Before the swap, window.nercone.cleanup() is called; after it, window.nercone.reinit(doc). To move from a script, call window.nercone.navigate(href).
